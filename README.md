# RadicalMart — ModulBank

Пакет интеграции [RadicalMart](https://radicalmart.ru/) и RadicalMart Express с интернет-эквайрингом Модульбанка для Joomla.

Плагин создаёт ссылку на оплату заказа, перенаправляет покупателя на платёжную страницу Модульбанка, принимает уведомления о транзакциях и меняет статус заказа после успешной оплаты.

## Возможности

- создание платёжной ссылки через API Модульбанка;
- работа с RadicalMart и RadicalMart Express;
- тестовый и боевой режимы;
- передача состава чека в Модульбанк;
- автоматическое формирование URL для уведомлений;
- проверка подписи, магазина, режима, суммы и валюты входящего callback;
- защита от повторной обработки одной транзакции;
- перевод заказа в выбранный статус после получения состояния `COMPLETE`;
- отдельное журналирование создания платежа и обработки callback;
- исключение ключей, подписей и персональных данных из диагностических сообщений.

## Требования

| Компонент | Требование |
|---|---|
| Joomla | 5.0 или новее |
| PHP | 8.5 или новее |
| PHP extension | cURL |
| Интернет-магазин | RadicalMart или RadicalMart Express |
| Эквайринг | подключённый интернет-эквайринг Модульбанка |

## Установка

1. Скачайте готовый файл `pkg_radicalmart_wishboxmodulbank.zip` из релиза либо соберите пакет из исходного кода.
2. В панели управления Joomla откройте **Система → Установка → Расширения**.
3. Загрузите ZIP-файл пакета.
4. После установки убедитесь, что плагин **RadicalMart Payment: WishboxModulBank** опубликован. Установщик пакета включает его автоматически.

## Настройка RadicalMart

Создайте или откройте способ оплаты ModulBank в RadicalMart и заполните его параметры.

| Параметр | Назначение |
|---|---|
| Доступен для статусов | Статусы заказа, при которых покупателю доступна оплата |
| Статус оплаченного заказа | Статус, который получит заказ после подтверждённой оплаты |
| Merchant ID | Идентификатор магазина в Модульбанке |
| Тестовый режим | Использование тестовой среды и тестового секретного ключа |
| Секретный ключ | Боевой секретный ключ интернет-эквайринга |
| Тестовый секретный ключ | Секретный ключ тестового режима |
| URL уведомлений | Сформированный плагином адрес для callback Модульбанка |
| Передавать чек | Передача товарных позиций в запросе на оплату |
| Отладка оплаты | Журналирование процесса создания платёжной ссылки |
| Отладка callback | Журналирование обработки уведомлений Модульбанка |

Для RadicalMart Express используются те же реквизиты эквайринга. Доступность оплаты и итоговый статус заказа определяются настройками RadicalMart Express.

### URL уведомлений

Плагин автоматически добавляет URL уведомлений в каждый запрос на создание платежа. Адрес также отображается в настройках способа оплаты и доступен для копирования.

Типовой адрес RadicalMart:

```text
https://example.com/radicalmart_payment/wishboxmodulbank/callback
```

Типовой адрес RadicalMart Express:

```text
https://example.com/radicalmart_express_payment/callback
```

Фактический путь зависит от параметра `payment_entry` соответствующего компонента. Callback должен быть доступен Модульбанку из интернета без авторизации и возвращать HTTP 200 после успешной обработки.

## Сценарий оплаты

1. Покупатель выбирает ModulBank и начинает оплату заказа.
2. Плагин формирует и подписывает запрос на создание счёта.
3. Модульбанк возвращает URL платёжной страницы.
4. Покупатель переходит на платёжную страницу.
5. Модульбанк отправляет callback о состоянии транзакции.
6. Плагин проверяет подпись и параметры уведомления.
7. При состоянии `COMPLETE` заказ переводится в настроенный оплаченный статус.

Обрабатываемые состояния платежа:

| Состояние | Значение |
|---|---|
| `PROCESSING` | платёж обрабатывается |
| `WAITING_FOR_3DS` | ожидается подтверждение 3-D Secure |
| `FAILED` | платёж завершился ошибкой |
| `COMPLETE` | платёж успешно завершён |

## Сборка пакета

Установите зависимости разработчика:

```bash
composer install
```

Соберите установочный ZIP с помощью входящего в рабочее окружение Phing PHAR:

```bash
php phing-latest.phar
```

Если Phing установлен глобально:

```bash
phing
```

Результат сборки появится в корне проекта:

```text
pkg_radicalmart_wishboxmodulbank.zip
```

Файл `phing-latest.phar` не хранится в Git и должен быть добавлен локально либо заменён глобальной установкой Phing.

## Тесты

Установите зависимости и запустите интеграционные тесты:

```bash
composer install
composer test
```

Обычный запуск использует локальный тестовый HTTP-сервер и не обращается к реальному API Модульбанка.

### Тест реального API

Скопируйте пример окружения:

```bash
cp .env.example .env
```

Заполните `.env`:

```dotenv
MODULBANK_RUN_LIVE_TESTS=1
MODULBANK_API_URL=https://pay.modulbank.ru/api/v1/bill/
MODULBANK_MERCHANT_ID=your-merchant-id
MODULBANK_TEST_SECRET_KEY=your-test-secret-key
```

Запустите только тест реального API:

```bash
vendor/bin/phpunit --filter ModulBankLiveApiTest
```

Тест создаёт счёт в тестовом режиме Модульбанка. Файл `.env` исключён из Git; не добавляйте в репозиторий реальные ключи.

## Диагностика

### HTTP 401: неверное значение `signature`

Проверьте:

- Merchant ID и секретный ключ принадлежат одному магазину;
- для `testing=1` указан тестовый ключ, а для `testing=0` — боевой;
- используется секретный ключ интернет-эквайринга, а не произвольный API-токен;
- время на сервере синхронизировано по NTP;
- значения не содержат пробелов в начале или конце.

При ошибке API сервис включает в исключение HTTP-код и сообщение из JSON-ответа Модульбанка.

### Ошибка SSL: self-signed certificate in certificate chain

Не отключайте проверку TLS. Добавьте официальные российские корневой и выпускающий сертификаты в системное хранилище доверия, затем перезапустите PHP-FPM.

Для AlmaLinux/RHEL:

```bash
sudo cp russian-trusted-root-ca.crt /etc/pki/ca-trust/source/anchors/
sudo cp russian-trusted-sub-ca.crt /etc/pki/ca-trust/source/anchors/
sudo update-ca-trust extract
sudo systemctl restart php-fpm
```

Для Debian/Ubuntu:

```bash
sudo cp russian-trusted-root-ca.crt /usr/local/share/ca-certificates/
sudo cp russian-trusted-sub-ca.crt /usr/local/share/ca-certificates/
sudo update-ca-certificates
sudo systemctl restart php-fpm
```

Сертификаты следует получать из официального источника: [Госуслуги — российские доверенные сертификаты](https://www.gosuslugi.ru/crt).

Проверка соединения:

```bash
curl -Iv https://pay.modulbank.ru/api/v1/bill/
```

### Callback не обрабатывается

Проверьте, что:

- сайт доступен по публичному HTTPS-адресу;
- URL уведомлений не закрыт Basic Auth, WAF или межсетевым экраном;
- веб-сервер не перенаправляет POST-запрос на другой домен или протокол;
- выбран правильный способ оплаты и сохранены его параметры;
- системное время сервера корректно;
- журналы callback включены в настройках способа оплаты.
